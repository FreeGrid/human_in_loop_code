### Delegation backend: Herdr

- This workspace explicitly uses Herdr for all subagent orchestration, regardless of whether the controller or child runs Pi, Codex or another supported agent. Create, prompt, inspect, wait for and reuse children through Herdr. Do not use the Pi `subagent` / `agent_message` tools or Codex-native spawn, messaging or wait tools for these children. Do not load the Pi collaboration skill to manage Herdr children.
- The shared delegation, continuity and independent-review rules above still decide whether to delegate and whether reuse is allowed. Herdr changes the execution mechanism, not acceptance authority. A Herdr child running Codex also delegates through Herdr; explicitly include this backend rule and the relevant control instructions in each task packet because the child's cwd may not contain this AGENTS.md.
- Read the installed `herdr` skill before operating Herdr. If it is missing, report the setup requirement: `npx skills add herdrdev/herdr --skill herdr -g`. Installation is a separate setup action; initialization does not install software. The reference is https://github.com/herdrdev/herdr/blob/v0.9.0/skills/herdr/SKILL.md; the installed skill and CLI help govern actual syntax.
- Before any Herdr control command, verify `test "${HERDR_ENV:-}" = 1`. If this fails, stop Herdr orchestration and report that the controller must run inside Herdr. Do not inspect a focused external session or fall back to Pi/Codex-native orchestration. Reading or generating these workspace files does not require Herdr.
- Discover syntax with `herdr --help`, then `herdr agent` and `herdr pane`. Never run bare `herdr` for discovery or probe mutating commands without arguments. Inspect layout with an explicit caller pane. Default to a sibling pane in the current tab and cwd, choose a suitable split direction, and preserve focus with `--no-focus`. Only use a different workspace, tab, worktree or cwd when explicitly requested.
- Create a shell pane first (for example `herdr pane split --current --direction right --cwd "$PWD" --no-focus`, adjusting direction to layout), then use the pane ID returned in JSON with `herdr agent start <unique-name> --kind <requested-kind> --pane <returned-pane-id>`. Agent start does not create layout. Discover supported kinds from the installed CLI; do not assume that every agent is installed or supported. Pass native agent arguments only after `--`.
- Wait for startup readiness before prompting. Use `herdr agent prompt <name> "<task packet>" --wait --timeout 60000`, then `herdr agent get <name>` and `herdr agent read <name> --source recent-unwrapped --lines 120` to inspect results. Use `herdr agent wait` for further bounded waits. Successful submission or an idle/done lifecycle state is not acceptance evidence. A blocked UI, timeout, unknown state or stalled prompt requires inspection; never blindly resend or approve a dialog.
- Record the session/server context, returned pane ID, live agent name, affinity key, scope and acceptance authority. Use returned IDs or unique live names, never inferred sidebar positions or another client's focused pane. Names refer to live occupants, not permanent recoverable Sessions. A fresh independent reviewer requires a fresh agent Session without the Implementer transcript; another prompt to the same agent is not fresh review.
- Keep write scopes disjoint and communicate scoped result capsules. If terminal output is truncated and another read cannot recover it, follow the skill's file-output fallback. Do not close panes or sessions you did not create, stop a server, or change user focus without the corresponding user instruction.
